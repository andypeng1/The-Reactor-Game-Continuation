# COVER —— 那块 1:1 的封面怎么做的（Phase 132；六边里的主体于 Phase 133 换成厂标）

> 一句话：`cover/index.html` 是一张 **1080×1080 的静止画**，
> 由 `_tools/intro_render.js`（和 `intro` / `promo` **共用**的那台渲染器）拍成一个 PNG，
> 再由 `_tools/cover_judge.js`（**没有浏览器**）判它的版面，
> 由 `_tools/cover_layers.sh`（**逐像素**）保证它的每一层装饰真的在画上。

---

## 1. 文件都在哪

| 文件 | 是什么 |
|---|---|
| `cover/index.html` | **画本身**。1080×1080，一个 `render(t)` 决定它长什么样（`t` 被忽略） |
| `cover/THE_REACTOR_GAME_cover.png` | **成品**。1080×1080。**像素是一幅、字节是两个形态**（§4 / §6）：792813 B / md5 `6feba9bd…`，或 792812 B / `f9e17bcd…` —— 落盘的是哪一个**每轮不一定**（Phase 133 连渲 12 次是 10/2） |
| `_tools/intro_render.js` | 渲染器（共用）。封面用到了它的 `--w` `--h` `--shot` 三个参数 |
| `_tools/cover_judge.js` | **判定**（A0..A10）。只读一份 JSON，不碰浏览器 |
| `_tools/cover_layers.sh` | **逐层关掉再渲染**，比像素：哪一层其实没画上 |
| `_tools/cover_layer_probe.py` | 上面那个脚本的比对器；顺带打素材极性表 |
| `_tools/cover_mark_check.py` | **六边里那 163512 个像素是不是这张素材**（对着素材自己的 alpha；吐一张阈值扫描表） |
| `cover_judge.js --selftest` 用的报告 | `_tools/_attic/scratch/cover_report.txt`（gitignore） |

**没有第二条运输线。** 封面和两部片子服从**同一份契约**：一个固定的设计空间 `#stage`、
一个全局的 `render(t)`、一个按视口缩放的 `fit()`。所以它不需要自己的渲染器 ——
`docs/PROMO.md` 那句「渲染器不用改：第二部片子就是又一个遵守同样契约的 HTML」
在这一轮第三次兑现（只是这次多了一个 `--shot`，因为**静止页面有一个要交付的帧**，
而默认的落点 `_attic/_frames` 是 gitignore 的垃圾堆）。

## 2. 四条命令

```bash
# 1) 拍成品帧，同时把版面读数倒出来
D:/nodejs/node _tools/intro_render.js --page cover/index.html --at 0 \
    --w 1080 --h 1080 --shot cover/THE_REACTOR_GAME_cover.png \
    --eval 'layoutReport()' > _tools/_attic/scratch/cover_report.txt

# 2) 判（exit 1 = 有红）
D:/nodejs/node _tools/cover_judge.js _tools/_attic/scratch/cover_report.txt
D:/nodejs/node _tools/cover_judge.js --selftest _tools/_attic/scratch/cover_report.txt

# 3) 每一层装饰到底改了几个像素（会重拍一次成品帧）
bash _tools/cover_layers.sh

# 4) 六边里那 163512 个像素是不是这张素材（对着素材自己的 alpha；吐扫描表）
python -X utf8 _tools/cover_mark_check.py        # 默认 t=120，也可以给 t
```

`--w 1080 --h 1080` **不是可选的**：视口必须钉成页面自己的舞台，否则 `fit()` 会把
方舞台缩进一个 1920×1080 的视口、截图上带黑边，**而报告里每一个坐标都是错的空间里的**。
这条现在是检查器的第一句（A0），因为它是"后面十条全都在量错的东西"的那种错。

## 3. 版面规则（A0..A10）

判定只读 `layoutReport()` 吐出来的 JSON。规则、它们的读数、以及**每条为什么要写成那个形状**：

| | 断言 | 读数 |
|---|---|---|
| A0 | 设计空间是 1080×1080 且填满视口 | stage 1080×1080 / viewport 1080×1080 |
| A1 | **非真空**：≥12 个文字块、4 个格子 | 13 blocks / 4 cells |
| A2 | 每个文字块都在外框以内 | 13 blocks inside [26..1054] |
| A3 | 没有两块撞上，**且**最近的一对不到 40px | 0 colliding；最近 4.00px |
| A4 | 标题放得下内宽、让开下面的细线 | w=901.0 of 1036，bottom 796 vs rule 806 |
| A5 | 六边主体在顶部细线和标题条之间 | x[290.58..789.41] y[116..692] |
| A6 | 面板盒子比例正好 `2/(2cos30)` | 1.154706 vs 1.154701 |
| A7 | CSS 百分比六边形 == SVG 像素六边形 | 逐顶点最差 0.012 px |
| A8 | 读数条每一格的值都在自己那格里 | slack 166/206/103/135 px |
| A9 | 没有一层装饰"画了等于没画" | 6 层，invert 与声明的极性全对上 |
| A10 | 六边里的厂标不捅出六边的边线 | 到最近那条边还剩 39.4 px |

**A3 和 A1 是"非真空"那一半**（§0.20：空集合会说两次谎）："没有两块相撞"在只画了
两块的页面上一文不值，所以 A1 先要求**有东西可撞**，A3 再要求"最近的一对**确实很近**"。
A8 是唯一一条关于"被吃掉"的断言 —— 逐格比，因为总值比对看不见一个值**越过分隔线**。
A10 是 Phase 133 新加的：厂标是**唯一一个不被 `clip-path` 裁切**的图层元素，它长得太大
只会"穿出那圈实线"，而画上那只是"一条线穿过另一条线"（取舍 **568**）。
**突变 13/13**，每一条只点亮它瞄准的那一条（`--selftest`）。最真实的那一条突变不是编的：
**忘了 `--w/--h`**，于是舞台被信箱化、报告里全是错空间的坐标。

## 4. 六个装饰层：Phase 132 真正的东西

`#grid` `#hexes` `#coreGlow` `#coreMark` `#titleBand` `#hazard` 是六个**靠 opacity /
混合模式活着**的层（`#coreMark` 是 Phase 133 换掉实拍时新加的那一层）。
它们没有文字、不落在任何几何断言上 —— 第一版里**四条是坏的，而十条规则里的九条全绿**。

| 层 | 旧写法 | 旧 vs 关掉 | 现在 vs 关掉 |
|---|---|---|---|
| `#titleBand` | `stripes.png`（**黑**）+ `screen`，无 invert | **0 px，Δ0** | 24294 px，Δ69 |
| `#hazard` | 同上 | **0 px，Δ2** | 14548 px，Δ46 |
| `#hexes` | `nested-hex.png`（**白** 235）+ `invert(1)` | 8480 px，**Δ3** | 256538 px，Δ24 |
| `#smMark` | `sm-logo.png`（**白** 228）+ `invert(1)` | 138 px，**Δ35** | 538 px，Δ54 |
| `#grid` / `#coreGlow` | 纯 CSS 渐变 | —— | 12476 px / 337266 px（本来就对） |
| `#coreMark` | ——（Phase 133 才有的层：`sm-core.png`，**白** 255，无 invert） | —— | 163512 px，Δ189 |

两种机制：**`screen` 对黑是恒等**（`screen(底,0)=底`，所以黑素材喂给 screen 的层
**逐像素为 0**）；**`invert` 作用在近白线稿上是把它转成黑**（层还在，振幅塌 1%–14%）。
"层不在"和"层在但读不出来"是**两个失败**，混成一句就两件都没说清（取舍 565）。

**`#coreMark` 另外还对着素材自己的 alpha 量过一次**（新的一层，不满足于"关掉有变化"——
**一个平铺的白色方块也能让这一层全绿**）。
命令是 `python -X utf8 _tools/cover_mark_check.py`，它把素材自己的 alpha 缩进页面给它的
那个 420×420 盒子，再给成品帧取阈值，**两个方向都数**。它的输出**不是一对数、是一张扫描表**，
因为**在这一页上没有干净的一刀**：

```
  t     bright      tp      fp      fn   precision   recall
   60     73785   44661   29124       2     0.6053    1.0000
  100     47839   43811    4028     852     0.9158    0.9809
  150     35542   35002     540    9661     0.9848    0.7837
  240         0       0       0   44663        nan    0.0000
```

**为什么没有干净的一刀**：厂标的墨（1% 分位 **95**、中位 189）和**不是墨的东西** ——
盒子里那**两条 HUD 读数**（接近白 **235–237**）—— **在亮度上重叠**。
所以 `precision` 在这一页上的分母里坐着**不是被测对象的东西**（§0.21 那一族的浅版）。
**能站得住的两句**：

1. **整份墨都在画上**：t≤60 时 **44663 个墨像素里有 44661 个是亮的**（缺 2 px）。
   这一句把"画的是这张素材"和"画了个亮的方块"分开了。
2. **变暗的是外圈，不是缺了一块**：按半径分档（t=120）—— r 0.0–0.8 全在 99.6%–100%，
   只有最外面那档 **r 0.9–1.0 落到 80.7%**（那一档装着 15478 个墨像素 = 全部墨的 35%，
   正是素材那个**粗外环**），是 `#hexTint` 把四周压暗。**"缺了一块"和"被压暗了"是两个失败**（§0.32 ②）。

> **同期更正：这一节原来写的那一对（precision 0.9972 / recall 0.7371）作废。**
> 它来自一次**没有记下参数**的临时量法，换成上面这个仪器之后**复现不出来**（取舍 **570**）。
> 现在参数写在仪器里、也打在输出上（盒子位置、阈值、alpha 门槛、整张扫描表）——
> **复现不出来的数不是懒，是它本来就是一次"挑出来的数"，不是量出来的数**（同 §0.22 ⑤）。
> 顺带：第一版仪器把素材 `convert("L")`，而它是 **LA**、**每个像素的 RGB 都是白的** ——
> 于是"墨"变成整个盒子（precision 1.0000 / recall 0.27）。**那个读数不是错的，
> 它是另一个问题的答案**：先量"画在哪一个通道"，再写比对器。

**复量这条跑道**：`bash _tools/cover_layers.sh` → 六层**每一层都必须 >0 px**，
且差值的外接矩形要落在那一层该在的地方（警示带 `y[1024..1051]`、标题条 `y[704..757]`、
厂标 `x[300..779] y[158..633]` = 它的盒子被 `drop-shadow(0 0 26px)` 撑出去一圈，
**这个对得上本身就是一次读数**，与 CSS 里写的逐字对上）。
它自己也能红：把 `#hexes` 的 `invert(1)` 加回去，这一层掉到 Δ3。

**`#grid` 那个数是个"构建读数"，不是常数。** 上一轮记的是 12461 px，这一轮 12476 px。
机制量过了：`#grid` 是一条 **5% alpha** 的线纹，而判据是 **Δ2** 的门槛 ——
所以**它盖住的东西越亮，越多个像素落在门槛之下**。实测厂标那块（墨是近白的）
线上密度 **0.05%**，厂标外面 **2.40%**，**比值 0.02×**：亮的底**压住**了这条线的读数
（我原来的猜测是反的 —— 猜"亮底更容易过门槛"，量出来是"更难"）。
结论不是"哪个数对"，而是这个数**只会告诉你这一次构建**。

**这条跑道自己的两个静默失败**（一次跑到第六遍才露脸，两个都不报错）：

- **`#grid` 的关灯帧不是逐字节可复现的。** 连渲 8 次，其中 2–3 次给出不同的 md5
  （Phase 132 那次 3/8，Phase 133 复量 2/8 —— **这个数本身每次都不一样**）——
  而那几个变体之间**逐像素最大只差 1**（`transform:perspective(…)` 的透视渐变重采样）。
  它正好落在 `DELTA=2` 的门槛附近，所以这一层的读数会在门槛上抖。
  **交付帧自己也在抖，只是更小**：连渲 5 次分成两个字节形态（3 次 792812 B / md5 `f9e17bcd…`，
  2 次 792813 B / `6feba9bd…`），两者**只差 1 个像素、1 个灰阶** ——
  (790,583) 的 G 通道对 (22,31,34) / (22,32,34)，而 x=790 正好是六边右边缘
  `hex.right = 789.41` 上取整后的第一列，即裁切边的抗锯齿。
  **像素上它是一幅画，字节上它不是**（§6 末）。
  Phase 133 换掉画面内容之后重量了一遍：**还是同一个像素、还是 Δ1** ——
  因为它量的是**裁切线**，与六边里装的是什么无关（那时 md5 换成上面那一对）。
- **更坏的一个是我自己的**：`render()` 原来把渲染器的 stdout 和退出码一起吞了
  （`> /dev/null`，不查 `$?`），于是**渲染失败会留下上一帧**，比对照样拿它当这次构建的读数。
  这是 §0.26① 同族 —— **判据能因为被测原因之外的原因给出一个数，它就不是实验**。
  有过一次这样的读数：`#grid 12493 px / 最大 Δ171`，而其余五遍和上一轮会话都是
  `12461 px / Δ16`（换掉主体之后这一层是 12476 px，见上一条）。**我没能复现它**，
  所以这里写的是"没复现"、不是一个结论；
  上面那条 stale-file 是**机制**、不是证据。现在的脚本每次 `cd` 到仓根、先删目标、
  渲染器没产出文件就 `exit 1`，并且在 `C:/` 下跑一次确认它不再依赖调用者的 cwd。

**A9 只抓得住样式那一半。** 素材的极性量不到（`file://` 下 canvas 读背景图会被污染），
所以每一层用 `data-art` **声明**极性，A9 断言"声明和 `filter` 一致"：
`white ⟺ 不许 invert`、`black ⟺ 必须 invert`、`gradient ⟺ 更不许 invert`
（反色只会产出调色板外的颜色）。**量出极性的命令写在声明的注释里** ——
这条断言检的是"声明自洽"，而声明的出处可复查。

## 6. 验了 / 没验

**验了：** 版面 A0..A10 十一条全绿（11 ok / 0 failed）；突变 13/13；
**渲染可复核**（同一个源连渲 12 次 → **逐像素最大差 Δ1、超过 Δ2 的像素 0 个**；
**md5 会因为那 1 个像素分叉成两个字节形态**（这一轮 10/2），
所以判据是像素不是哈希 —— §4 那条）；
六层装饰每层都改变像素，且差值落在正确的位置上；新加的 `#coreMark` 另对着素材自己的
alpha 量过一次（§4 那张**扫描表**：整份墨都在画上、变暗的是外圈）；
读图三次（Phase 132 修之前一次、修之后一次；Phase 133 换成厂标之后一次）——
最后一次确认**厂标轮廓清楚、不越出六边、HUD 读数仍然可读、整体不挤**；
**缩略图看了**（Phase 133 补的）：480×480 与 256×256 各拍一张读一次 ——
**大字两个尺寸都读得出**、**六边 + 厂标两个尺寸都还认得出形状**，
**四格和 HUD 的小字两个尺寸都读不出**（256 上一格只有 ~58 px 宽）。
这是"海报缩略图"的正常层级，**不是缺陷**，所以没有改字号（改字号会毁掉 1:1 的版面）。

**没验（不许外推）：**

- **全程没进 Studio、没进 Play、没上传过任何地方**（§0.16 边界不变）。纯磁盘产物。
- **缩略图那两张是用 `--w 480 --h 480` 把整台舞台等比缩下来拍的**，所以它们是
  "同一幅画缩小的样子"，**不是**"商店页真会怎么裁/怎么压"（那边的编码、DPI、圆角
  都没进过这次测量）。
- **读图那个模型在 480 上会编字。** 它报出了 `CZB2-8A`、`CAUTION`、`0224 W`、
  `COMPONENT INTEGRITY 97.6%` —— **这些字符串在页面里一个都不存在**。
  所以"小字读不出来"这个**负**结论可信（与算术一致：13px × 0.44 ≈ 5.8px），
  而它在小尺寸下报出的**任何具体字符串都不算读数**。
- 读图用的是兜底模型（`glm-4.5v`），**它是"看起来对不对"的证人，不是尺子** ——
  它的每一句判断都要和读数对上才算数（§0.14b）。
- **没有做"换主体之前 / 之后并排"读图**（Phase 133）：换完之后的读图是**单张**的，
  所以"厂标比实拍更合适"这句话**没有测量支持** —— 它是操作员的判断。
  这一轮能验的只是"这一层确实在画上、而且是这张素材"（§4 那张扫描表）。
