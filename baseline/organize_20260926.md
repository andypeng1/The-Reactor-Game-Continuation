**31** instances were listed as deleted. The missing 6 were the **children of
`CreepySounds`**, destroyed with the script.

They are **not recoverable**. They were destroyed before I inspected them, so I cannot say what

`{"path":"Workspace.CreepySounds","disabled":true,"class":"Script","placeholder":true,

What argues they were harmless: the script was `Enabled=false`, a `placeholder:true`

children.** A disabled script with live children is not an inert subtree, and I treated it as
one. The lesson is narrower than "be careful" — the safety argument I ran was about the
*script*, and I let it cover the *unit*.

## 4. The rollback, and what its real key is

`ServerStorage.OrganizeRollback20260926` — a **single `StringValue`**, `HttpService:JSONEncode`
of 779 records, **197602 bytes**. Six fields per record:

    name   cls   cf (12 numbers, from CFrame:GetComponents())   size   color   mat

It lives in **ServerStorage** and not in Workspace precisely because SS does not replicate.
Proven live, not assumed: `rollback record leaked to client (must be false): false`.

### Its key is the CFrame, not the name

A `name`-keyed restore **does not work here**, and this was measured rather than reasoned about.
768 of the 779 parts are named literally `Part`, plus `Line` and friends. A name index over
`Geometry` matched only **344** records, and a sample line came back
`Part cls=Part geo=true root=true` — the same name resolving in two containers at once.

Position works. Tolerance match at 0.05 studs over every BasePart in Workspace:

| result | records |
|---|---|
| exactly one part at the recorded position and size | **768** |
| no part there | **0** |
| more than one (coincident twins) | 11 |

**779 of 779 are present.** The 11 coincident ones are a property of the art — stacked parts
the same size in the same place — and for those, restore is ambiguous by position *and* by
name, so they are the only records that need a human eye.

### Two wrong readings I discarded before writing them down

Both were my measurement, not the data, and both are recorded because each looked like a real
defect for one call:

1. **A `%.3f` string key on the CFrame.** It reported 55 (then 66) of 779 as missing. The
   misses were a rounding boundary: a recorded double and a live float32 land either side of
   the 3rd decimal, so `%0.3f` prints `342.427` for one and `342.428` for the other. The tell
   was that widening the search *lowered* the hit count — impossible for a real absence. Fixed
   by tolerance matching, which returned **0 missing**.
2. **A name-keyed index.** It reported `inGeometry=344, inNeither=435`, which reads like 435
   parts lost. It is not: my branch counted a name found in *both* containers as "neither",
   and with 768 parts named `Part` that is the common case, not the exception.

## 7. `verify_docs.py` is obsolete, and that is why it was archived

With docs no longer mirrored into Studio (the operator's answer B4, 2026-09-26) there is no

(`before/tampered/restored` all read `section 0.0 is 7051 bytes, expected 6071`).

A check that is always red is noise, and it is the same disease §0.13 names in another costume:
a path that cannot be distinguished from success. Retired rather than repaired, because with
mirroring gone there is nothing left for it to check.
