
### 0.36 【坑】一句「实测」里坐着**两个数**时，问它们**各自**来自哪一次读数；而一个字母可以在两块里是**两个量**

Phase 140（操作员贴来一整份规格，末尾「不需要我多说什么了」）。两条，都属
§0.18 那一族，但骗的是**写**的那一半。

**① 84 是量的，79 / 5 是写的 —— 而它自己抄进了三份文档。**
冷却那侧的证否句是"出厂日志有 **84 条** `CBL sum 0` 而泵在转"。
围着它的拆分写着「**79 是开机前、5 是崩塌后**」—— **这两个数不来自任何一次读数**：
那 84 条能试的判据全试过（泵档 / `tempF` / `fluctuation` / `cbl.sumLevel` / `active`），
**只出一种拆分：62 / 22**。两个数**加起来正好 84**、**正好落在那句话里**、
**已经抄进三处**（`gui.py` / `_tools/coolant_from_log.py` / `README.md`），
**每一处都带着"这是量出来的"的语气**。处理照旧：**原文保留 + 当日更正 + 写明哪一半是量的**
（§0.14 / §0.29 / §0.34 ②）。
**一个数被量过，不代表它旁边那个也被量过** ——
"一句实测里有两个数"这件事本身就是个该**多问一句**的形状。
同日同族一条更小的：`gui.py` 写「顶上是 5.39x」，而**算出来是 5.38** ——
`0.1032a + 1.1` 在 `a = 125` 是 14.0，14.0 / 2.6 = 5.3846。
**"这个数看起来像什么"和"这个数是多少"在盘上逐字同形。**

**② 同一个字母在两块里是两个量，而**一句注释**能定下标约定。**
他这一份里 `s` 出现两次：热那块 `s = {T < 5600: 0, …}` 是**0 基的行**（有第 0 行），
压力那块 `p_base = {s == 1: 110, …}` **没有 0**，只能是 latch 住的 `Sim.State`（1..3）。
**定案的不是哪一块看起来更顺，是"哪个键有独立来源"**：`110/350/800` 就是 `STATE_GAIN`
（`calculation.luau:34` + 我们 `Config`，**两个来源**）。
然后**驱动"能把两者分开的那一拍"**：`T = 12000` 时行是 **1**、压力表给 **500**、
行的拼法是 **−130** —— **两份读法必须能在某一拍上给出不同的数**（§0.20 ②）。
`passive[s+1]` 的 `+1` 是**第三种**约定（他的列表 1 基），**靠他自己那句注释定案**：
「状态 1 = −400，状态 2 = −422」—— 按 0 基读列表则状态 1 会是 −422，**矛盾的是那个读法**。
**一个表达式里三层下标约定，靠一句注释和两个独立来源的键定下来。**

**③ 一条连带（规格重述）：** 他这一份十行里**七行是旧的**（压力那四行逐字就是这台控制台
从第一版在跑的那一行**去掉 PEA 项**，而 `PEA_GAIN[1] = 0` ⇒ 他的式子正是 PEA = 1 档）。
**"两处都在"不是判据，"两处都对"才是** —— 判据拿**他的字面量**驱动、两份拼法互相比较。
**重述比新东西难：新东西你会去查，重述的你会点头。** 取舍 **600..605**，
系统 `docs/SYSTEMS.md` **§2.32**，配方 `docs/SNIPPETS.md` **§5.45**。
