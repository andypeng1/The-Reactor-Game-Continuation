
## R11 — 泵的 120 是量出来的，但你的热线比原版陡 2.6 倍，冷却在**这台**控制台里变弱了（2026-10-16，Phase 136）

你问「冷却控制呢？三个冷却泵分别控制」—— 办完了，三台泵各 0..3 档接在控制台上。
**这一条不是"没做完"，是一个我量出来、又不想自己抹平的不一致。**

**先说数是从哪来的（三处同源，最强的那处是读出来的）：** 出厂日志
`Data/DataCollection.Log` 每一拍都记着原版**自己**算的 `predictions.predDT`，而

```
predDT * 5  ==  65*sum(cbl.level) - 120*sum(coolant.levels)     -- 477 条，最大误差 0.0
```

所以 **120 是"一台跑着的原版"给出来的读数**，不是我从源文件里抄的
（`_tools/coolant_from_log.py` 跑给你看）。这一点没有分歧。

**分歧在另一头。** 你这台控制台吃的**热量**是你拟合的那条线，
而它大约比原版的 **65 / CBL 档陡 2.6 倍**：

| | 原版 | 你这台控制台 |
|---|---|---|
| 每档 CBL 的热 | **65** | 行 1 是 `6.86 × 25 = 171.5`（**2.638 倍**） |
| 九档泵 = **1080** 度/拍 | **大于**它自己的最大激光热（65×15 = 975）—— 满泵能压过满激光 | 行 1 三台满档 = **41.2%**（行 2 39.2%、行 3 35.0%），**还是压力倍数之前** |

**一句话**：同一个 120，在原版里能把最大火力压下去，在这里只能拿掉四成。
**两边各自都对，是这台控制台的热线比原版陡。**

**三个选项：**

- **A.（现状）留着量到的 120。** 这台控制台的定位是"**原始游戏的模型**"，
  而原版的泵就是 120 —— 一个读出来的数就是读数。
  代价：**在这台控制台上泵的手感比原版弱**，你拨的时候会有这个感觉，这是真的。
- **B. 把泵折算到你那条线（120 × 2.638 ≈ 317/档）。** 恢复"九档泵能压过三台满档激光"
  这个**比值**。代价：**317 里没有一个是别人的读数**，它是我拿 120 乘一个我自己算出来的比
  —— 而且它一改，这台控制台就不再是"原版的模型"了。
- **C. 回头查那条热线。** 真正可疑的可能是**热**那一侧不是**冷**那一侧：
  如果你手上有更多层级的数据、或者你知道那条线只是在 `a = 25..125` 上拟合的，
  那**这台控制台的火力本来就偏大**，该动的是 `ACTIVE`，不是 120。

**我按 A 办的**（`gui.py` 里那条 KNOWN DIVERGENCE 注释就是这一条），
因为 `CLAUDE.md` §1.4 那条"不要在没有依据的情况下改"在这儿也管用：
**动 A 只是不加东西，动 B/C 是我发明一个数**。你要哪个都行，说一声。
