### 2.32 核心模型的**热**：一条曲线取代四行直线，`passive` 移出关闸（Phase 140，2026-10-16）

操作员贴来一整套规格（结尾「**不需要我多说什么了**」），`luau-windows/gui.py` 的模型据此定型。
**这一节只讲"这台控制台的核心模型现在是什么"**；它是怎么被逐条读懂的见取舍
`DECISIONS_2` **600..605**，全文 `PROGRESS.md` Phase 140。

**现在的一拍（`Core.step` + `Sim.tick`，顺序是 `Engine.luau` 的：先温度，后压力）：**

```
row        = core_state(T)                       温度的纯函数，0..3
a_avg      = ((c1 + c2 + c3) / 3) * 25           三台激光的平均，0..125
pure_cbl   = {a_avg <= 0: 0,                     他自己的零门
              0.0516*a_avg^2 + 1.1*a_avg + 426}  一条曲线，行不在里面
passive    = [-455.7, -400, -422, -22][row]      行唯一决定的东西
p_mult     = {P <= 11500: 1, P <= 27000: 2, 4}   只乘 pure_cbl
noise(t)   = (a_avg/25) * (15 sin(t/1.5) + 10 sin(t/0.7) + 5 sin(t/0.3))
coolant    = 120 * mean(p1..p2..p3)              三台泵的**平均**（Phase 139）
dT         = {P <= 2200: -586,                  失速吞掉整条 dT
              pure_cbl*p_mult + passive - coolant + noise}
T'         = T + dT

dP         = p_base[s] + T' * p_temp_mult[s] - 60*fans + PEA[s]   s 是 latch 的 Sim.State
```

**三处与 Phase 139 不同的地方，三处都是他的规格带进来的：**

| | Phase 139（旧） | Phase 140（新） |
|---|---|---|
| 热 | `active[row]` = **一行一条直线**，行改斜率也改截距 | `pure_cbl(a)` = **一条曲线**，行不在里面 |
| 全黑的控制台 | **原地不动**（整行贡献在那道关闸后面） | **按自己那一行的速率降温**（`passive` 在门外） |
| `p_mult` 乘什么 | 整个 `base`（passive 也在里面） | **只乘 `pure_cbl`** |

**被判据钉住的几个数**（`core_model_check.py` 232 项 / 0 失败）：

- 他自己那个状态块（`c=p=0`、`fans=6`、`T=20000`、`P=7000`、`t=1`）驱动一拍：
  `row 2`、`pure_cbl 0`、`passive -422`、`noise 0` → **T 20000 → 19578**；
  压力那一半 **dP = 136.835**，因为那一行读的是**这一拍结束时**的温度 19578
  （按开始时的 20000 会是 140 —— **两个时刻，不是一个错**）。
- **拟合顶端 `a = 125`**：`pure_cbl(125) = 1369.75`，按行配上 `passive` 是
  **914.05 / 969.75 / 947.75 / 1347.75**（屏上是 `914 / 970 / 948 / 1348`）。
  满冷却 **360** 对它们 = **39.4% / 37.1% / 38.0% / 26.7%**（原版自己的同一条是 110.8%）。
- **"陡多少倍"不再是一个数**：曲线的斜率 `0.1032a + 1.1` 对原版的每 a 单位 2.6 是
  **1.42x（a=25）/ 2.41x（50）/ 5.38x（125）**，退役的直线是处处 2.638x。
- 两个 state 分开的那一拍：`T = 12000` → **行是 1**，压力表给 **500**，行的拼法是 **−130**。

**三个给操作员看的字符串也跟着改了**（读数标签 `pure_cbl  0.0516 a^2 + 1.1 a + 426` /
`passive  this row's constant` / `activeFluc  pure_cbl x press`，面板标题
`dT = pure_cbl * p_mult + passive[s] - coolant + noise   (or exactly -586, stalled)`）。
**检查器读得到第一和第三个**（`activeFluc` 那一条是 Phase 140 才修好的陈旧键），
**读不到标题** —— 那一条防线照旧只有改完 grep（取舍 591）。

**这一项没有外部证据。** 出厂日志里**没有一台活着的、四个控制全关的堆芯**
（`CBL sum 0` 且泵全关的 39 条 `GameActive` 全 false），所以 `passive` 的四个数是他的、
按字面实现的，**日志既不证实也不否证**（`_tools/passive_from_log.py`，取舍 602）。

**压力递推不是新的**：他那四行是这台控制台从第一版就在跑的那一行**去掉 PEA 项**
（`PEA_GAIN[1] = 0`，所以他的式子正是 PEA = 1 档的情形）。**PEA 的去留进了 `QUESTIONS.md` R13。**
